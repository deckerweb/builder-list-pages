Sonderfälle und Erkennungsgrenzen

English · Builder-Übersicht

Mosaic

Erkannt werden direkte, gespeicherte Layout-Zuweisungen im aktuellen Mosaic-Theme. Automatische Template-Zuweisungen, gelöschte Layouts und globale Header/Footer zählen nicht dazu. Beim Wechsel auf eine andere Multisite-Website innerhalb derselben Anfrage wird Mosaic nicht ausgewertet. Mosaic selbst benötigt WordPress 6.9 und PHP 8.2; Builder List Pages behält WordPress 6.7 und PHP 8.1 bei.

Vorlagenimporte und Theme-Erweiterungen

Kadence Starter Templates und Starter Templates von Brainstorm Force sind keine eigenen Builder. Entscheidend sind die importierten Kadence-, Spectra- oder anderen Builder-Inhalte. Die Importer müssen danach nicht aktiv bleiben. Kadence Theme Kit Pro und Beaver Themer können globale Layouts zuweisen; das beweist keine direkte Bearbeitung des Seiteninhalts.

Block-Nutzung und Premium-Funktionen

Ein erkannter Block belegt die Verwendung einer Blockfamilie. Er bestätigt weder eine Premium-Lizenz noch, dass jede dynamische Funktion aktuell verfügbar ist. Erweiterungen bestehender Blöcke sind nicht in jedem Fall separat erkennbar. Der Kadence-Seitenassistent allein zählt nicht als Seiteninhalt. Allgemeine CSS-Angaben und der gemeinsame Spectra-AI-Block werden nicht als eindeutiger Builder-Nachweis verwendet.

Wiederverwendete Inhalte

Verschachtelte Blöcke und veröffentlichte, lesbare synchronisierte Vorlagen werden geprüft. Zum Schutz vor Schleifen gilt eine Begrenzung auf 20 Referenzebenen und 200 Vorlagenverweise je Inhalt. Andere externe Vorlagen oder Inhalte aus Abfragen werden nicht automatisch verfolgt.

Zähler, Datenschutz und Leistung

Zähler beziehen sich auf lesbare Inhalte außerhalb des Papierkorbs. Suche und weitere Listenfilter können die sichtbare Ergebnismenge reduzieren. Gemischte Seiten können in mehreren Builder-Gruppen stehen. Die Erkennung verändert keine Inhalte, rendert keine Builder und sendet keine Seiteninhalte an externe Dienste. Ergebnisse werden nur für die laufende Anfrage zwischengespeichert.

Genesis Blocks und Atomic Blocks

Genesis Blocks wird anhand gespeicherter Genesis-Blöcke erkannt. Unveränderte ältere Atomic-Blocks-Inhalte zählen nicht automatisch dazu. Eine Umwandlung von Inhalten übernimmt Builder List Pages nicht.

Thrive Architect und Theme Builder

Erkannt werden gespeicherte Architect-Merkmale direkt am Inhalt. Thrive Theme Builder kann den Architect-Kern ebenfalls laden. Seine Aktivität oder ein global zugewiesenes Theme-Template beweisen deshalb keine direkte Architect-Bearbeitung jeder Seite. Elementor Pro wird entsprechend innerhalb der Elementor-Familie erkannt; globale Pro-Templates zählen nicht automatisch als direkt bearbeiteter Seiteninhalt.

Inhaltstyp-Auswahl

Die automatische Auswahl berücksichtigt Builder-Freigaben und WordPress-Eigenschaften. Bekannte Verwaltungsdaten wie Menüs, Redirect-Regeln, Consent-Einträge, Formularverwaltung und Protokolle werden ausgelassen. post_content allein ist kein Eignungsnachweis: Builder können Inhalte in Metadaten speichern, und technische Datensätze können ebenfalls Text enthalten.

Unter Einstellungen → Builder List Pages → Inhaltstypen anpassen hat jede manuelle Website-Auswahl Vorrang vor der automatischen Klassifizierung. Einbeziehen prüft gespeicherte Erkennungsmerkmale; native Builder-Freigaben, Bearbeitungsrechte und harte Systemausschlüsse gelten weiterhin. Auch nicht öffentliche eigene Inhaltstypen ohne normalen Editor können bei ausdrücklicher Auswahl berücksichtigt werden. Ausblenden wirkt auf Übersicht, Spalte, Filter, Untermenüs, Befehle und die zugänglichen Typen für CSV/Favoriten. Daten und Builder-Einstellungen bleiben erhalten.

Entwicklerfilter

deckerweb_builder_list_pages_content_type_allowed erhält die automatische Entscheidung, das WP_Post_Type-Objekt und die Builder-ID. Ein boolescher Rückgabewert ändert die Vorauswahl. Explizite Website-Ausnahmen werden danach angewendet. Berechtigungen, Systemausschlüsse und native Builder-Freigaben können dadurch nicht umgangen werden.

add_filter( 'deckerweb_builder_list_pages_content_type_allowed', function ( $allowed, $type, $builder ) {
    if ( 'my_private_portfolio' === $type->name && 'oxygen-classic' === $builder ) {
        return true;
    }
    return $allowed;
}, 10, 3 );

Die Einstellungen blp_settings[post_type_rules] gehören zur einzelnen Website. Temporär nicht registrierte Typen behalten ihre Auswahl. Mit Automatisch lässt sich eine Ausnahme entfernen. Deaktivierung und Deinstallation erhalten diese Einstellungen; keine Datenbankänderung an fremden Inhalten erfolgt.

Etch

Direkt gespeicherte Etch-Blöcke werden erkannt, auch innerhalb gemischter Inhalte oder ausdrücklich eingebundener synchronisierter Patterns. Etch muss für aktive Filter geladen und verfügbar sein. Das Etch-Theme allein, globale Header und Footer sowie automatisch verwendete Templates werden einer Seite nicht zugerechnet.

CrocoBuilder

Erkannt wird der eigene Aktiv-Schalter am Inhalt. Nach Rückkehr zum WordPress-Editor zählen verbliebene Layoutdaten allein nicht. Auch ein aktivierter Inhalt ohne gespeichertes Layout kann deshalb als CrocoBuilder erscheinen. Die in CrocoBuilder erlaubten Inhaltstypen gelten zusätzlich zu den Plugin-Einstellungen. Voraussetzung: WordPress 7.0 und PHP 8.2.

Builderius

Free und Pro bilden eine gemeinsame Integration. Erkannt werden aktivierte, direkt einem Inhalt zugeordnete Seiten-Templates mit passender ausdrücklicher Inhalts-ID. Zusätzliche kontextabhängige Regeln, globale Vorlagen und automatische Zuweisungen zählen nicht. Die Zuordnung beschreibt den gespeicherten Editor-Stand, nicht den tatsächlich live ausgespielten Release oder dessen Inhalt. Bei deaktivierten Templates entfällt der Treffer. Eigene Inhaltstypen benötigen die entsprechende Pro-Einstellung. Voraussetzung: PHP 8.2; geprüft mit Free und Pro 1.4-beta. Auf älterem PHP bleibt diese Integration pausiert, ohne andere Builder abzuschalten.
